# Technical Writing Style Guide — Kayfa

Used only when content_type="technical_writing". Marketing content follows brand_voice_guide.md instead.

## Structure

Every technical guide follows: prerequisites, then numbered steps, then a short troubleshooting note. Each step states the action first, then the expected result, so the reader can self-verify before moving on.

## Accuracy over persuasion

No hype language, no CTA, no hashtags. A technical guide's job is correctness, not conversion. If a step is uncertain or version-dependent, say so explicitly rather than presenting it as universally true.

## Formatting conventions

- Commands, file names, and exact values go in monospace/code formatting, never prose-styled.
- Version numbers are stated explicitly wherever a step could behave differently across versions (e.g. "as of CrewAI 1.15.x" rather than assuming permanence).
- Each step is self-contained enough that a reader who skipped the intro can still follow it.

## Tone

Still Kayfa's voice underneath — clear, direct, no jargon for jargon's sake — just without the persuasive/marketing layer on top.
